## Design rationale for the reveal rule

The task spec says "If the player has NEVER locked an archetype (i.e., it's not in `archivedArchetypes`), show ???". The current `archivedArchetypes` only updates on `triggerPrestige()`, so a strict reading would mean a freshly-locked archetype in the current run still shows `???` until prestige. That would be jarring UX (player just locked X but the panel says ???). The reveal helper therefore treats the currently-locked archetype as known: `isArchetypeKnown = archivedArchetypes.includes(id) || lockedArchetype === id`. This way:
- First time locking X (this run): name shown throughout the run (player gets feedback on their choice).
- After prestige: X is in `archivedArchetypes`, so future runs reveal X's identity everywhere (resource bar chip, evolve warning, StagePanel dominant caption, locked display, radial graph labels).
- An archetype the player has never locked (across any run, including the current run) shows `???` / `?` everywhere.

## Unresolved Issues / Risks
1. **Mammalian glyph placeholder**: `archetypes.ts` still has `glyph: "denti"` for the Mammalian archetype (a 5-char word instead of a single sigil). The radial graph truncates this to `"d"` so the label fits, but the LockedArchetypeDisplay and ResourceBar chip still show the full `"denti"` text. This is pre-existing data — fixing it (e.g. replacing with a tooth-related Unicode glyph) is out of scope for this task but worth noting.
2. **Color leaks identity**: per the task spec, unknown archetypes still use their real `ARCHETYPE_MAP[id].color` in the radial graph. A player who has locked a green archetype before could deduce that another green dot is the same archetype. This is intentional per spec ("Use each archetype's color"), but if stronger mystery is desired, the color could be muted/desaturated for unknown archetypes in a future pass.
3. **Pulse animation performance**: SMIL `<animate>` is used for the dominant dot's pulse. SMIL is supported in all modern browsers but is technically deprecated in the Chrome spec (still works in practice). If perf becomes an issue, this could be moved to CSS keyframes with `transform-box: fill-box`.
4. **No end-to-end playtest of the reveal flow**: I verified compilation and lint, but did not play through a full Creature→Tribal evolve + prestige to manually confirm the ??? → name transition in the browser. The logic is unit-verifiable via `isArchetypeKnown` and the helper is exercised by the components, but a visual playtest is recommended.
