    21→  2020→## Design Rationale
    22→  2021→1. **Why allow buying more of the chosen variant?** The exclusiveWith lock is about *which path*, not *how far down it*. The chosen variant can still scale up to `maxOwned` (e.g. cell walls can be bought multiple times for more capacity; ascension spires are `maxOwned: 1` so this only matters for cell wall + creature movement variants). Locking the chosen variant after one purchase would make the choice feel like a dead-end.
    23→  2022→2. **Why only lock on first purchase?** Subsequent purchases of the chosen variant don't change the decision — the choice was already made. Locking repeatedly would be redundant work and would also re-fire if somehow the player sold/lost systems (which the game doesn't support, but defensive design is cheap).
    24→  2023→3. **Why group via `exclusiveWith` references rather than a separate `variantGroup` field?** Mirroring the existing TechDef pattern keeps the data model consistent. The grouping algorithm in `partitionVariantGroups()` already handles the symmetric-reference case correctly.
    25→  2024→4. **Why show locked siblings at all (rather than hiding them)?** The player should see the path NOT taken — it reinforces that the choice was meaningful and helps them plan future runs. This matches the TechTab pattern where locked techs still display with "Locked — chose X instead" text.

   283→  2282→## Design Decisions
   284→  2283→
   285→  2284→1. **Enlightenment unlock fires from `checkChallengeCompletion`, not `triggerPrestige`**. The popup fires the instant the 10th challenge is mastered (during gameplay), not on the next prestige. The `triggerPrestige` path is a defensive fallback for legacy saves that already had 10 challenges done before this code shipped.
   286→  2285→
   287→  2286→2. **Divinity formula follows the spec literally**: `Math.floor(score / 500 * stageMult)`. For a Galactic run with score ~5000 and stageMult=64, that's ~640 Divinity per prestige. With nodes costing 5-25 each, a player who has unlocked Enlightenment can buy most nodes in 1-2 prestiges. This is intentional — Divinity is the currency for layers 2-8 (Transcendence, Genesis, Apotheosis, Singularity, Omnipotence, Divinity layers), so accumulating it now seeds those future layers.
   288→  2287→
   289→  2288→3. **Route bonus stacks additively with archetype + challenge-mastery + foresight bonuses**. All four are independent additive multipliers applied to the production rate. Keeps math simple and avoids multiplicative explosion.
   290→  2289→
   291→  2290→4. **Route bonus applies to BOTH system production (tick) AND manual actions (performAction)**. Same pattern as the existing archetype bonus — both auto and manual gain the route's benefit.
   292→  2291→
   293→  2292→5. **Foresight nodes provide passive bonuses that stack with achievements + challenge mastery**. Most grant +2-5% production (target: "production"); some grant per-resource bonuses (target: "resource" with resourceId). The `foresightBonus()` helper is function-overloaded so the same call works for both.
   294→  2293→
   295→  2294→6. **3 nodes are `implemented: false` (coming soon)**: destiny_lock (route binding/doubling), compressed_frontiers (skip mastered stages), cosmic_relay (auto-carry forward). These represent future systems that would require more substantial implementation. They show in the tree but can't be purchased — gives the player a sense of the full Enlightenment arc without overpromising.
   296→  2295→
   297→  2296→7. **`spendDivinity(amount, nodeId)` is a low-level primitive** — the UI uses `purchaseForesightNode` (high-level, does full validation + deduction). The low-level `spendDivinity` is kept for future ritual/transaction uses (e.g., Transcendence layer's Offerings per the design doc spec).
   298→  2297→
   299→  2298→8. **Route selection is a toggle** — click to bind, click again to unbind. Lets the player change their mind mid-run. Only one route active at a time (`selectedRoute` is a single string).
   300→  2299→
   301→  2300→9. **Layer 2 "mastered" status** requires both: (a) all *implemented* foresight nodes purchased AND (b) a route chosen. This way the player can't skip the route choice — it's the central mechanic of the layer.
   302→  2301→
   303→  2302→10. **Migration is defensive**. Old saves (pre-Task-19) load with `divinity: 0`, `selectedRoute: null`, `foresightNodes: {}`. If the player had all 10 challenges done before this code shipped, `enlightenmentUnlocked` is set to `true` immediately on load — so they get the button + modal without having to re-prestige.
