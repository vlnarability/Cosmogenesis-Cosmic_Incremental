  2916→## Design Decisions
  2917→
  2918→- **Effect fields spread directly on each def, not bundled under a
  2919→  `bonus` sub-object.** Mirrors `transcendence.ts`'s `RitualEffect`
  2920→  pattern and `genesis.ts`'s `CradleWorldDef` pattern. Lets the
  2921→  consumer read `law.productionMult` directly instead of
  2922→  `law.bonus.productionMult`. The `DivineLawBonus` RETURN type (from
  2923→  `divineLawBonus`) is the aggregated object — distinct from the def
  2924→  type. This avoids duplicating field definitions across def and
  2925→  bonus interfaces.
  2926→
  2927→- **`worshipMult` is multiplicative; all other mults are additive.**
  2928→  The spec says "2× worship bonus" for Faith — a multiplier, not an
  2929→  additive bonus. So `worshipMult: 2.0` means "double the worship
  2930→  bonus" and aggregates via `result.worshipMult *= law.worshipMult`
  2931→  (starting from 1.0). If a future law also sets `worshipMult`, they
  2932→  would compound (e.g. Faith ×2 and another ×1.5 → ×3.0). Currently
  2933→  only Faith sets it.
  2934→
  2935→- **`heresyFlatOnCodify` is on the law def, not in `DivineLawBonus`.**
  2936→  Faith's −20 heresy is a one-time effect applied at codification
  2937→  (not per tick), so it doesn't belong in an aggregate that's
  2938→  recomputed each tick. The consumer reads `DIVINE_LAW_MAP["law_faith"].
  2939→  heresyFlatOnCodify` once when the player codifies Faith and applies
  2940→  it to `state.heresy`. Matches the genesis.ts `divinityFlat` pattern
  2941→  for Wisdom Seed (one-time grant on awakening).
  2942→
  2943→- **`heresyDecays` is a UI flag, redundant with `heresyRateMult: −2.0`.**
  2944→  Mercy sets both. `heresyRateMult: −2.0` makes the math work out
  2945→  (effective rate = 0.05 × (1 + −2.0) = −0.05/s, heresy decays at
  2946→  base rate). `heresyDecays: true` is purely informational — the UI
  2947→  can read it to render "Decaying" on the heresy meter without
  2948→  having to interpret whether `heresyRateMult` makes the net rate
  2949→  negative. The validator doesn't enforce coupling; future laws
  2950→  could set one without the other.
  2951→
  2952→- **`heresyRateMult` helper combines laws + worship mode.** The
  2953→  spec lists 4 helpers, and `heresyRateMult(laws, modeId)` reads
  2954→  BOTH sources in one call. Internally it calls `divineLawBonus(laws)
  2955→  .heresyRateMult` (so the law-side aggregation is computed once and
  2956→  shared) then adds the active mode's `heresyRateMult` if set. This
  2957→  avoids the consumer needing to call two helpers and sum them.
  2958→
  2959→- **`worshipModeBonus` returns the `WorshipModeDef` itself, not a
  2960→  subset.** Only one worship mode is active per run, so there's no
  2961→  aggregation — the helper is just a typed lookup. Returning the def
  2962→  (with `id`/`name`/`desc`/`icon`) means the consumer can also use
  2963→  the returned object for UI display without a second lookup.
  2964→
  2965→- **`isApotheosisComplete` takes two explicit arguments.** The spec
  2966→  says "Codify 3 Divine Laws and resolve a Heresy schism" — two
  2967→  distinct conditions. Passing `heresySchismResolved: boolean`
  2968→  explicitly (rather than asking the caller to derive it from
  2969→  `HERESY_RESPONSES["inquisition"]` use counts) keeps the helper
  2970→  decoupled from the store's schism-detection logic. The store will
  2971→  flip `state.heresySchismResolved` to true when Inquisition is
  2972→  invoked (the canonical schism-resolving response).
  2973→
  2974→- **`MIRACLE_ALL_RESOURCE_TARGETS` is pre-computed and exported.**
  2975→  The Manna miracle grants "+50 all resources" — meaning every
  2976→  primary resource. Pre-computing the list (filtering `RESOURCES`
  2977→  by `category === "primary"`, 24 entries) avoids the store having
  2978→  to re-import `RESOURCES` and re-filter. Excludes prestige
  2979→  currencies (`divinity`, `evolution_points`, etc.) so Manna
  2980→  doesn't grant free Divinity or EP. Matches the genesis.ts
  2981→  `RESOURCES.filter(r => r.category === "primary")` convention.
  2982→
  2983→- **`Tolerate` uses `limitPerRun: Infinity` and `cost: 0`.** The
  2984→  validator explicitly permits `Infinity` as a limit value (no upper
  2985→  bound check; only `>= 1`). Tolerate is the "do nothing" option —
  2986→  the player can always choose to let heresy rise. Documented in
  2987→  the `HeresyResponseDef` JSDoc.
  2988→
  2989→- **`grantAllResources` semantics documented.** Miracles that grant
  2990→  "all resources" use `grantAllResources?: number` (flat amount to
  2991→  every primary resource). The consumer iterates
  2992→  `MIRACLE_ALL_RESOURCE_TARGETS` and adds the amount. Mirrors how
  2993→  genesis.ts `WorldCapBonus` with `target: "all"` expands across
  2994→  `RESOURCES`.
  2995→
  2996→- **IIFE validator runs at module import.** Matches the
  2997→  `transcendence.ts` and `genesis.ts` pattern. Validates: id
  2998→  uniqueness within each family, each law/mode sets ≥1 effect,
  2999→  each miracle sets exactly one effect (XOR), `cost`/`limitPerRun`
  3000→  sign checks, `worshipMult >= 1`, `happinessTarget ∈ [0,100]`,
  3001→  `setHappiness ∈ [0,100]`, `productionBoost.mult > 1`,
  3002→  `BASE_HERESY_RATE > 0`, `HERESY_MAX > 0`. Single pass at load;
  3003→  no-op on the hot path.
  3004→
  3005→- **No state fields or store wiring in this file.** Pure data +
  3006→  helpers, mirroring `transcendence.ts` and `genesis.ts`. The
  3007→  wiring is a follow-up task (likely L5-wire). Verified by
  3008→  `grep -r "lawsCodified\|worshipMode\|miracleUses\|heresyResponse\|\
  3009→  heresySchism" /home/z/my-project/src` — only matches are in
  3010→  `prestigeLayers.ts` (story text in the Apotheosis layer definition)
  3011→  and the new `apotheosis.ts` itself.
